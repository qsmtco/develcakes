## Bug 1: MED-7 Sanitization Strips Bug Journal Headings (CRITICAL — causes test failure)

**File:** `utils/feedback_processor.py` (around line 157-175)
**Problem:** The MED-7 sanitization loop strips ALL lines starting with `#` (markdown headings), including the `## Bug #N` heading that `to_bug_journal_entry()` generates. This causes `test_bug_severity_appended_to_journal` to fail because the heading is missing from the journal entry.
**Root cause:** `line.strip().startswith('#')` is too aggressive — it matches structurally required headings generated by the code itself, not just injection attempts.
**Fix:** Apply sanitization only to user-controlled field values (task, bug_description, expected, actual, pattern) BEFORE passing them to `to_bug_journal_entry()`, NOT to the generated heading. OR: change the heading strip to only match headings that don't match the `## Bug #N —` pattern. The heading is generated by `to_bug_journal_entry()` and is always safe.
**Test to verify:** `python3 -m pytest tests/test_agent_command_handler.py::TestAuditReportProcessing::test_bug_severity_appended_to_journal -v` — must PASS

## Bug 2: LOW-3 GET /agents AttributeError — Always Returns Empty List (HIGH)

**File:** `agent/kb_server.py` (around line 253-258)
**Problem:** The GET /agents handler accesses `a.name` on `SpecialAgentDef` objects, but `SpecialAgentDef` has no `name` attribute — it has `display_name`. This raises `AttributeError`, caught by bare `except Exception`, silently returning `{"agents": []}`.
**Root cause:** Attribute name mismatch. `SpecialAgentDef` uses `display_name`, not `name`.
**Fix:** Change `a.name` to `a.display_name` on the line that builds the agent_ids list.
**Test to verify:** Add a test that registers agents, hits GET /agents, and verifies the returned list matches.

## Bug 3: A-4 Audit Log `user` Field Always Empty (MEDIUM)

**File:** `agent/runtime.py` (lines 1679, 1699, 1774) and `agent/config.py`
**Problem:** The audit log records `user=getattr(self._config, "user_id", "")` but `AgentConfig` has no `user_id` field, so this always evaluates to `""`. The audit log entries contain no user identity information.
**Root cause:** `AgentConfig` was never extended with a `user_id` field.
**Fix:** Add `user_id: str = ""` field to `AgentConfig` in `agent/config.py`. Wire it through at runtime initialization if a user identity is available. The `getattr` fallback will then pick it up.
**Test to verify:** After a tool execution, assert that `audit_log.entries[-1].user` is not empty (when a user_id is configured).

## Bug 4: A-9 Agent ID Label Never Populated (MEDIUM)

**File:** `ui/window.py` (lines 621-625, 797-800)
**Problem:** The status bar label `self._agent_id_label` is created with default text `"Agent: —"` and the method `update_agent_id_display()` exists, but no code ever calls it. The label always shows "Agent: —".
**Root cause:** The method was defined but never wired to any callback.
**Fix:** Call `self.update_agent_id_display(agent_id)` from the gateway connection handler after successful connect, using the agent_id from the gateway identity or snapshot.
**Test to verify:** After connecting to the gateway, verify the status bar label text is not "Agent: —".

## Bug 5: LOW-1 user Field Uses Session Key, Not User Identity (LOW)

**File:** `ui/handlers/task_handler.py` (line 107)
**Problem:** LOW-1 sets `user=cmd.source_session_key` (e.g., `"agent:qaster:telegram:direct:7478874934"`), not an actual user identity. The spec says "user identity for traceability" — a session key is not a user identity.
**Root cause:** No user identity is available in the `Command` model.
**Fix:** Add a `user: str = ""` field to `Command` in `models/command.py`. Populate it at parse time from the gateway identity or a configured username. Alternatively, for now, use a human-readable label from the session key (e.g., the last segment).
**Test to verify:** Verify that `task.user` is a human-readable identity, not a raw session key.
